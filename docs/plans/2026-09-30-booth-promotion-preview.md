# 부스홍보게시판 미리보기

작업 브랜치: `feat/booth-promotion-preview`. main 머지 및 운영 DB 변경은 수행하지 않는다.

## 확인 경로

- `/booth-promotion/preview`: 샘플 3개로 배치도, 상세, 즐겨찾기, 작성·수정, 회원별 권한을 확인한다. 등록·이미지 선택·수정은 메모리에서만 처리하며 새로고침하면 초기화된다.
- `/booth-promotion`: 실제 Supabase 데이터를 사용한다. 아래 마이그레이션이 먼저 필요하다.
- 대학생활의 기존 부스 목록에 배치도 링크를 추가했다.

## 구현

- 문서 편집본 배치도 40칸: 거11 / 위11 / 와7 / 토3 / 끼8. 부스 등록 여부 및 즐겨찾기에 따라 배경과 테두리를 구분한다.
- PageHeader, 상세 Dialog, 부스 등록 폼, 이미지 업로드 UI, 좋아요 저장을 재사용한다.
- 관리자 폼 필드를 BoothFormFields로 분리하고 일반 부스어 폼에서도 사용한다. 홍보 폼에는 비밀번호 및 호버 이미지 항목을 표시하지 않는다. 기존 데이터는 보존한다.
- 기존 booths / booth_keywords / booth_participants / booth_likes를 공유한다. 홍보 화면 수정은 대학생활에도 반영된다.
- 작성자 ID는 서버 세션에서 정한다. 업데이트 RPC에서 행을 잠그고 본인 여부를 검사한다. 부스와 참가자·키워드는 하나의 트랜잭션으로 저장한다.
- 위치 유효성 및 중복은 DB 제약으로도 검사한다. RPC는 service_role만 호출할 수 있다.
- 관리자 폼에서 기존 부스의 위치, 인포 링크, 작성자 계정 ID를 지정할 수 있다. 부스명 일치만으로 기존 데이터를 자동 귀속시키지 않는다.

## 실제 데이터 적용 전

1. 별도 테스트 Supabase에서 `20260930100000_booth_promotion.sql`을 적용한다.
2. 기존 부스의 위치와 실제 작성자 계정을 운영자가 연결한다. 작성자만 연결한 부스는 해당 부스어 화면에 위치 등록 버튼이 표시된다.
3. 테스트 계정 2개로 본인 수정, 타인 수정 거부, 동일 위치 동시 저장 충돌, 이미지 업로드, 트랜잭션 롤백을 검증한다.
4. 화면 확인 후 사용자 승인에 따라 운영 DB 적용과 main 머지를 별도 진행한다.

Preview 배포에서도 이 마이그레이션을 운영 DB에 자동 적용하지 않는다. 샘플 미리보기는 DB 마이그레이션 없이 확인 가능하다. 앱 공통 Supabase 공개 환경변수는 기존 앱과 동일하게 필요하다.

## 실행

기존 환경변수 구성 후 `npm install` 및 `npm run dev`로 실행한다. 기존 package-lock.json은 npm ci에서 플랫폼별 선택 의존성 누락 오류가 있어 이번 기능에서 의존성 파일은 수정하지 않았다.

타입 검사: `npx tsc --noEmit`
기존 테스트: `node --test tests/*.test.js`
브라우저 테스트: dev 서버를 3000 포트에 실행한 뒤 `npx playwright test tests/booth-promotion.spec.ts --workers=1`

## 모바일 수정

- 640px 미만에서는 가로 스크롤을 없애고 배치도 5개 행을 화면 너비에 맞춘다. 실제 부스 배치는 유지하며 세로 간격을 늘려 모든 칸에 최소 44×44px 터치 영역을 확보한다.
- 상세 하단 버튼과 하트·닫기는 모바일 터치 크기를 확보한다. 상세 이미지 높이를 제한하고 긴 정보는 모달 안에서 스크롤한다.
- 등록 폼은 동적 화면 높이(dvh)에 맞춰 내부 스크롤하며 저장·취소를 하단에 유지한다. 입력 글씨는 16px로 설정해 iPhone 입력 시 자동 확대를 방지한다.
- 320 / 390 / 430px에서 모든 칸의 경계, 버튼 겹침, 상세 및 수정 동작을 브라우저 테스트로 검증했다.
